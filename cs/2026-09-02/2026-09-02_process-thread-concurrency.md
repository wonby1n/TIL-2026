# 프로세스, 스레드와 동시성 기초

## 프로그램, 프로세스, 스레드

```text
💾 프로그램 파일
   │ 실행
   ▼
⚙️ 프로세스
   ├─ 🧵 스레드 1
   ├─ 🧵 스레드 2
   └─ 🧵 스레드 3
```

- **프로그램**: 저장장치에 있는 실행 파일
- **프로세스**: 프로그램을 실행해 메모리와 운영체제 자원을 할당받은 실행 단위
- **스레드**: 프로세스 안에서 실제 명령을 실행하는 단위

프로그램 파일 하나를 여러 번 실행하면 일반적으로 여러 프로세스가 생성된다. 같은 프로세스의 스레드는 코드와 힙 등의 자원을 공유하지만 각자의 스택을 가진다.

## 컨텍스트 스위칭

CPU 코어를 작업대, 스레드를 직원으로 비유할 수 있다.

```text
🧵 직원 100명
🖥️ 작업대 4개
→ 일부만 동시에 실행하고 나머지는 대기·교대
```

CPU가 실행할 스레드를 교체하면서 기존 상태를 저장하고 다음 상태를 불러오는 과정을 **컨텍스트 스위칭**이라고 한다.

스레드가 지나치게 많으면 다음 비용이 생길 수 있다.

- 상태 저장과 복원 비용
- CPU 캐시 효율 저하
- 스레드별 스택으로 인한 메모리 사용 증가
- DB, 네트워크, 락을 기다리는 시간 증가

## 경쟁 상태와 락

여러 스레드가 공유 데이터를 동시에 수정해 실행 순서에 따라 잘못된 결과가 발생하는 현상을 **경쟁 상태(Race Condition)**라고 한다.

```text
잔액: 10,000원

스레드 A: 10,000원을 읽고 1,000원 출금
스레드 B: 10,000원을 읽고 1,000원 출금

잘못된 결과: 9,000원
정상 결과:   8,000원
```

**락(Lock)**은 한 번에 하나의 스레드만 특정 자원에 접근하게 해 경쟁 상태를 막을 수 있다. 대신 다른 스레드의 대기 시간이 늘고, 서로 상대방의 락을 기다리면 **교착 상태(Deadlock)**가 발생할 수 있다.

## 핵심 요약

> 프로세스는 실행 중인 프로그램이고 스레드는 그 안의 실행 단위다. 스레드는 자원을 공유하므로 동시 수정 시 경쟁 상태가 발생할 수 있으며, 락은 이를 막는 대신 대기 비용과 교착 상태 가능성을 만든다.
