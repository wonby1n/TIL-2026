# CI/CD, 이미지 레지스트리와 운영 설정

## 환경변수

동일한 Docker 이미지라도 실행 환경에 따라 다른 설정을 주입할 수 있다.

```text
📦 동일한 my-app 이미지
 ├─ DB_HOST=dev-db  → 개발 환경
 └─ DB_HOST=prod-db → 운영 환경
```

개발 DB 주소를 코드에 고정하면 운영 서버도 개발 DB에 접속하거나 연결에 실패할 수 있다. 코드와 환경별 설정을 분리해야 한다.

## Secret 관리

DB 비밀번호와 API 키 같은 민감정보는 공개된 Compose 파일이나 Git에 평문으로 저장하지 않는다.

```text
❌ Git 저장소에 비밀번호 기록
✅ Secret 저장소에서 실행 시 주입
```

Git에서 현재 파일을 삭제해도 과거 커밋에 값이 남을 수 있다. 인증정보가 노출됐다면 먼저 폐기·교체하고, 이후 기록과 로그를 정리해야 한다.

## 이미지 레지스트리

이미지 레지스트리는 Docker 이미지를 저장하고 배포 서버에 전달하는 중간 저장소다.

```text
⚙️ Jenkins
 │ docker build
 ▼
📦 my-app:a84f12c
 │ docker push
 ▼
🏬 Registry
 │ docker pull
 ▼
🖥️ 운영 서버 → 🐳 컨테이너 실행
```

Docker Hub, AWS ECR, GitHub Container Registry 등이 있다.

## 추적 가능한 이미지 태그

```text
my-app:1.2.3
my-app:a84f12c
my-app:latest
```

`latest`는 고정된 버전이 아니라 다른 이미지를 가리킬 수 있는 태그다. 운영 배포에서는 버전이나 Git 커밋 ID가 포함된 태그를 사용하면 실행 중인 코드를 추적하고 이전 버전으로 롤백하기 쉽다.

## 재시작 정책과 재시작 루프

Docker는 애플리케이션이 비정상 종료됐을 때 컨테이너를 자동으로 재시작할 수 있다.

```text
Spring 실행
  ▼
DB 인증 실패
  ▼
컨테이너 종료
  ▼
자동 재시작
  └─ 설정을 고치지 않으면 반복 🔁
```

재시작 정책은 일시적 장애의 복구를 돕지만 잘못된 환경변수나 코드 오류를 해결하지는 않는다. 반복 종료 시 `docker logs`, `docker ps -a`, `docker inspect` 등으로 원인을 확인한다.

## 애플리케이션 서버와 DB 병목

오토스케일링으로 Spring 서버를 늘려도 모든 서버가 하나의 느린 DB를 사용하면 문제가 해결되지 않을 수 있다.

```text
☕ Spring A ─┐
☕ Spring B ─┼──▶ 🗄️ 느린 DB
☕ Spring C ─┘
```

DB 병목은 느린 SQL과 인덱스, 캐시, 커넥션 풀, DB 자원, 읽기 복제 등의 관점에서 별도로 조사해야 한다.

## 핵심 요약

> Jenkins는 테스트·이미지 생성·Push·배포를 자동화하고, 레지스트리는 이미지를 전달한다. 운영 설정과 Secret은 이미지 밖에서 주입하며, 추적 가능한 태그와 헬스체크를 사용해 안전하게 배포한다.
