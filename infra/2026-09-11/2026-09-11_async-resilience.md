# 비동기 처리와 외부 서비스 장애 대응

## 동기와 비동기

오래 걸리는 AI 생성 작업을 HTTP 요청 안에서 끝날 때까지 기다리면 연결과 서버 자원을 오래 점유한다. 비동기 방식은 작업을 먼저 접수하고 별도 작업자가 처리한다.

```text
📱 생성 요청 → ☕ API 서버 → 📨 작업 큐 → 🤖 Worker
                  └─ 접수 응답       └─ 결과 저장
```

## 메시지 큐

메시지 큐는 처리할 작업을 잠시 보관한다. Worker가 일시적으로 느리거나 중단돼도 큐가 작업을 보존하고 복구 후 다시 처리할 수 있다.

관련 기술로 RabbitMQ, Kafka, AWS SQS 등이 있지만 목적과 전달 특성이 서로 다르므로 요구사항에 맞춰 선택해야 한다.

## 재시도와 지수 백오프

외부 API가 일시적으로 실패하면 재시도할 수 있다. 쉬지 않고 재시도하면 장애 서버의 부하를 더 키울 수 있으므로 간격을 늘린다.

```text
1차 실패 → 1초 대기
2차 실패 → 2초 대기
3차 실패 → 4초 대기
```

## 멱등성

같은 요청을 여러 번 보내도 최종 결과가 한 번 처리한 것과 같도록 만드는 성질이다. 결제 요청에 고유 키를 부여하면 응답 유실 후 재시도하더라도 중복 결제를 방지할 수 있다.

```text
결제 키 payment-123
├─ 첫 요청 → 결제 처리
└─ 재시도 → 기존 처리 결과 반환
```

## 서킷 브레이커

외부 AI 서버가 지속적으로 실패할 때 호출을 잠시 차단해 Spring의 스레드와 연결이 함께 고갈되는 것을 막는다.

```text
연속 실패 감지
☕ Spring ──X──▶ 🤖 장애 중인 AI 서버
     └─ 빠른 실패 또는 대체 응답
```

일정 시간이 지나면 시험 요청으로 복구 여부를 확인할 수 있다.

## 핵심 요약

> 오래 걸리는 작업은 비동기로 분리할 수 있고, 외부 호출에는 제한된 재시도·백오프·멱등성·서킷 브레이커를 조합해 장애가 전체 서비스로 번지는 것을 줄인다.
