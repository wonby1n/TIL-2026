# Uptime Kuma 운영: 터널 접속과 알림 연결

> Kuma의 역할과 장애 후 로그 확인은 [2026-09-16 노트](../2026-09-16/2026-09-16_uptime-kuma-monitoring-logs.md) 참고. 이 노트는 실제 서버에 붙여 쓰면서 헷갈렸던 부분만 정리한다.

```text
🐻 Kuma ──주기적 요청──▶ 🌐 https://도메인/api/health
   └─ 실패 감지 ──▶ 💬 Mattermost 알림
```

## 관리 화면을 공개하지 않는 구조

방화벽은 22/80/443만 열어두고, Kuma 관리 화면은 서버의 `127.0.0.1`에만 바인딩했다.

```yaml
ports:
  - "127.0.0.1:3002:3001"   # 서버 자기 자신만 접근 가능
```

외부에서는 접속할 수 없으므로 SSH 로컬 포트포워딩(터널)으로 들어간다.

```bash
ssh -i <키파일> -L 3003:127.0.0.1:3002 ubuntu@<서버>
```

```text
💻 내 PC localhost:3003 ══SSH 터널══▶ 🖥️ 서버 127.0.0.1:3002 ──▶ 🐻 Kuma
```

- 브라우저 주소창에 `localhost:3003`이 보이는 게 정상이다. 실제로 보고 있는 건 서버의 Kuma다.
- 터널을 연 터미널을 닫으면 `localhost:3003`도 접속이 안 된다. Kuma가 죽은 게 아니다.
- 알림은 Kuma가 서버에서 밖으로 보내는 요청이라, 관리 화면을 공개하지 않아도 정상 동작한다.

## 헷갈렸던 점: localhost의 두 가지 의미

| 위치 | 의미 |
|---|---|
| 브라우저 주소 `localhost:3003` | 내 PC에 열린 터널 입구 (정상) |
| 모니터 감시 URL에 `localhost` | Kuma 컨테이너 자기 자신을 가리킴 (잘못된 설정) |

감시 대상 URL은 반드시 실제 공개 주소(`https://도메인/...`)로 등록해야 한다.

## 함정: 알림을 만들어도 모니터에 연결해야 한다

Kuma에서 알림(Mattermost 등)은 두 단계로 동작한다.

```text
1. 알림 채널 생성 (웹훅 URL 입력)
2. 각 모니터에 그 알림을 연결 ← 이걸 빠뜨리면 다운돼도 알림이 안 옴
```

알림만 만들어 두고 연결을 안 해서, 사이트가 죽어도 Kuma 화면에만 빨갛게 뜨고 Mattermost로는 아무것도 안 가는 상태였다.

한 번에 해결하려면 설정 → 알림 → 기존 알림 **편집**에서 다음 두 가지를 체크한다.

- ☑ **기본 알림으로 설정**: 앞으로 만드는 모니터에 자동으로 연결된다.
- ☑ **기존 모니터링에 모두 적용하기**: 이미 있는 모니터 전체에 연결된다.

**테스트** 버튼으로 실제 메시지가 오는지까지 확인한다. 알림 종류를 일반 `Webhook`으로 새로 만들 필요 없이, 기존 `Mattermost` 타입 알림을 재사용하면 된다.

## 핵심 요약

> 관리 화면은 SSH 터널로만 열어 공개 노출을 막고, 감시는 공개 URL로 한다. 알림은 만드는 것만으로 끝이 아니라 모니터에 연결해야 실제로 발송된다.
